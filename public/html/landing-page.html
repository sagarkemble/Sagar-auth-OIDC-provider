Features

Everything you need

Built on proven standards with a focus on security, developer experience, and production reliability.

OAuth 2.0 Auth Code Flow
Industry-standard authorization with secure code exchange and redirect URL validation for every client application.
RS256 JWT Tokens
Asymmetric signing with RSA 2048-bit keys. Access tokens expire in 15 minutes, refresh tokens rotate every 7 days.

How it works

From registration
to token in 4 steps

The standard Authorization Code flow, implemented cleanly with full redirect URL validation and client isolation.

1
Register your client app
Submit your app name and redirect URL. Receive a unique clientId and clientSecret.
POST /client/register
2
Redirect user to login
Send your user to the login page with your clientId. They see the consent screen and authenticate.
GET /auth/login?clientId=…
3
Exchange the auth code
Your server exchanges the short-lived code for an access token and refresh token pair.
POST /auth/token
4
Fetch user identity
Use the Bearer access token to retrieve OIDC claims: email, name, picture, and more.
GET /auth/userinfo
token-exchange.js 
// 1. Exchange auth code for tokens
const res = await fetch('/auth/token', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    authorizationCode: code,
    clientSecret: CLIENT_SECRET,
  }),
});

const { accessToken, refreshToken } = await res.json();

// 2. Fetch user profile
const user = await fetch('/auth/userinfo', {
  headers: {
    Authorization: `Bearer ${accessToken}`,
  },
}).then(r => r.json());

// user.sub, user.email, user.name, user.picture …
Security

Built secure by default

Every layer of the system is designed with security as the primary constraint, not an afterthought.

RSA 2048-bit Signing
Asymmetric RS256 key pairs. Private key never leaves the server. Clients can verify tokens using the public key.
Bcrypt Password Hashing
All passwords are hashed with bcrypt before storage. Plain text passwords never touch the database.
SHA-256 Token Hashing
Auth codes, refresh tokens, and client secrets are SHA-256 hashed at rest. Only hashes stored in the database.
Short-Lived Tokens
Access tokens: 15 min. Auth codes: 5 min. Email tokens: 5 min. Short windows minimize breach impact.
Redirect URL Validation
Every token exchange validates the redirect URL against registered client configuration. No open redirects.
Zod Schema Validation
Every incoming request is validated against strict Zod schemas before reaching business logic. No malformed data passes through.
